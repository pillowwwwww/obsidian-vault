# 实验二
用了[[矩阵投影]]知识：

你的三类实验，其实都围绕同一个 reference direction（参考方向）

$$D_k = u_k v_k^\top$$

展开。也就是：先从某个 client 的某层 LoRA-B 里抽出第 $k$ 个奇异方向，再问这个方向：

- 在同 client 的另一 seed 里还在不在
    
- 在别的 client 里多不多
    
- 在别的 client 里是不是反着来
    
- 一平均后还剩多少
    
- 聚合后还剩多少
    
- 删掉它会不会伤本地性能
    

这就是整个实验链条。

## 一、先统一“方向”是什么

对某一层的 LoRA-B 矩阵做 SVD（奇异值分解, singular value decomposition）：

$$B = U\Sigma V^\top = \sum_{k=1}^{K}\sigma_k u_k v_k^\top$$

这里：

- $\sigma_k$：第 $k$ 个 singular value（奇异值）
    
- $u_k$：left singular vector（左奇异向量）
    
- $v_k$：right singular vector（右奇异向量）
    

你现在把第 $k$ 个方向定义为：

$$D_k = u_k v_k^\top$$

把第 $k$ 个带强度的成分定义为：

$$C_k = \sigma_k u_k v_k^\top$$

对应到代码里，SVD 分解和这些量的组织是在 `svd_utils.py` 里完成的。

## 二、最核心的基础量：projection（投影）

所有分数几乎都来自同一个基础量：

把别的矩阵 $B'$ 投影到 reference direction（参考方向） $D_k$ 上。

数学上：

$$\alpha(B';D_k)=u_k^\top B' v_k$$

为了让不同方向之间可比，代码里会再除以 reference 的奇异值 $\sigma_k$，变成 normalized projection（归一化投影）：

$$p(B';D_k)=\frac{u_k^\top B' v_k}{\sigma_k}$$

它的含义很直观：

- $p \approx 1$：说明 $B'$ 在这个方向上和 reference 很接近
    
- $p \approx 0$：说明 $B'$ 在这个方向上几乎没有成分
    
- $p < 0$：说明 $B'$ 在这个方向上和 reference 反向
    

这个量在代码里对应的是 `normalized_projection(...)` 这一类逻辑，定义在 `svd_utils.py` 和 `direction_metrics.py` 里。

## 三、四类分数怎么理解

你前面说的“四类分数”，我建议就固定理解成这四组：

1. stability / specificity（稳定性 / 特异性）
    
2. conflict（冲突）
    
3. fragility（脆弱性）
    
4. functional importance（功能重要性）
    

下面逐个解释。

#### 1）stability / specificity（稳定性 / 特异性）

这类分数回答：

- 这个方向是不是同一个 client 稳定学出来的，而不是 seed 噪声？
    
- 它是不是更像这个 client 自己的，而不是大家都有？
    

**1.1 same_presence**

数学公式：

$$\text{same\_presence} = \left| \frac{u_k^\top B_{\text{same seed2}} v_k}{\sigma_k} \right|$$

这里：

- $u_k, v_k, \sigma_k$ 来自 reference checkpoint
    
- $B_{\text{same seed2}}$ 是同一个 client、另一 seed 的 LoRA-B
    

含义：取绝对值，是因为这里只关心“这个方向在不在”。值越大，说明这个方向在同 client 的另一 seed 中也稳定出现。

代码指标名：`same_presence`。

**1.2 diff_presence**

数学公式：

$$\text{diff\_presence} = \frac{1}{C-1}\sum_{c'\neq c} \left| \frac{u_k^\top B_{c'} v_k}{\sigma_k} \right|$$

含义：看别的 client 在这个方向上有多少投影。值越大，说明这个方向不是这个 client 独有，别人也有很多。

代码指标名：`diff_presence`。

**1.3 pls_dir**

数学公式：

$$\text{pls\_dir} = \text{same\_presence} - \text{diff\_presence}$$

含义：同 client 稳定存在，其他 client 相对较少，那么这个方向更像 client-specific direction（客户端特异方向）。值越大越好。

代码指标名：`pls_dir`。

**这一组分数的实验意义**

这组分数主要服务于：

- Module A：direction-level conflict profiling（方向级冲突剖析）
    
- 以及 Module C 里的后续关联分析
    

你可以把它们理解成：先筛出“像 personalization（个性化）”的方向。

#### 2）conflict（冲突）

这类分数回答：

别的 client 在这个方向上，是顺着来，还是反着来？如果反着来，那 FedAvg（联邦平均）就更容易把它抵消掉。

**2.1 mean_signed_projection**

数学公式：

$$\text{mean\_signed\_projection} = \frac{1}{C-1}\sum_{c'\neq c} \frac{u_k^\top B_{c'} v_k}{\sigma_k}$$

含义：这是“有符号”的平均投影。正值代表别的 client 在这个方向上整体偏同向，负值代表别的 client 在这个方向上整体偏反向。

代码指标名：`mean_signed_projection`。

**2.2 signed_conflict**

数学公式：

$$\text{signed\_conflict} = \frac{1}{C-1}\sum_{c'\neq c} \max\left(0, -\frac{u_k^\top B_{c'} v_k}{\sigma_k}\right)$$

含义：如果别的 client 在这个方向上的投影是正的，不算冲突，记 0；如果是负的，说明反向，会造成 destructive cancellation（破坏性相消），就累计其大小。值越大，说明这个方向越 conflict-prone（更容易冲突）。

代码指标名：`signed_conflict`。

**这一组分数的实验意义**

这组分数还是主要用在 Module A，但会进一步喂给：

- Module B：作为 selector（选择规则），选出高冲突方向做 ablation（消融）
    
- Module C：看高冲突方向是不是聚合后保留更差
    

也就是：冲突是“为什么会被聚合伤害”的机制线索。

#### 3）fragility（脆弱性）

这类分数回答：

这个方向在“平均”或“聚合”之后还能剩多少？

这里其实有两种 fragility（脆弱性）：pairwise fragility（两两平均脆弱性）和 post-aggregation fragility（聚合后脆弱性）。

**3.1 pairwise_retention_under_avg**

这是 Module A 里的量。

先对 reference client 和另一个 client 做 pairwise average（两两平均）：

$$B_{\text{avg}} = \frac{1}{2}(B_c+B_{c'})$$

沿 reference direction 的保留率是：

$$\text{retention}_{pair} = \left| \frac{u_k^\top B_{\text{avg}} v_k}{\sigma_k} \right|$$

由于 reference 自己在该方向上的 normalized projection 约等于 1，代码里会把它化成等价形式：

$$\text{retention}_{pair} = \left| 0.5\cdot\left(1+\frac{u_k^\top B_{c'}v_k}{\sigma_k}\right) \right|$$

再对所有其他 client 求平均：

$$\text{pairwise\_retention\_under\_avg} = \frac{1}{C-1}\sum_{c'\neq c}\text{retention}_{pair}$$

含义：越大代表平均后这个方向还保得住，越小代表平均后更容易被抵消。

代码指标名：`pairwise_retention_under_avg`。

**3.2 fragility_pair**

数学公式：

$$\text{fragility\_pair} = 1 - \text{pairwise\_retention\_under\_avg}$$

含义：越大说明在 pairwise averaging（两两平均）下越脆弱。

代码指标名：`fragility_pair`。

**3.3 retain_after_agg**

这是 Module C 里的量，比较的是 same-round pre/post aggregation（同轮聚合前后）。

reference direction 还是来自 pre-agg local checkpoint：

$$D_k = u_kv_k^\top$$

然后把 post-agg global checkpoint 的矩阵投影上去：

$$\text{retain\_after\_agg} = \left| \frac{u_k^\top B_{\text{global post}} v_k}{\sigma_k} \right|$$

含义：越大代表这个本地方向在服务器聚合后还保留得比较好，越小代表聚合把它抹掉得更多。

代码指标名：`retain_after_agg`。

**3.4 fragility_after_agg**

数学公式：

$$\text{fragility\_after\_agg} = 1 - \text{retain\_after\_agg}$$

含义：越大说明这个方向经过真实聚合后越脆弱。

代码指标名：`fragility_after_agg`。

**这一组分数的实验意义**

这组分数把“冲突”变成“后果”：

- Module A 里先看 pairwise average 的脆弱性
    
- Module C 里再看真实 server aggregation（服务器聚合）后的脆弱性
    

逻辑上是：方向冲突 → 平均保留率下降 → 聚合后更容易消失。

#### 4）functional importance（功能重要性）

这类分数回答：

这个方向 / 这一组方向 / 这个 band，到底对本地性能有没有用？

这组不再只是“结构分数”，而是 intervention（干预）后的功能验证。

**4.1 remove / keep-only 重构公式**

对某层：

$$B = \sum_k \sigma_k u_k v_k^\top$$

选择一个方向集合 $S$。

remove selected directions

$$B' = \sum_{k\notin S}\sigma_k u_k v_k^\top$$

keep only selected directions

$$B' = \sum_{k\in S}\sigma_k u_k v_k^\top$$

然后把 $B'$ 回填到模型，再跑 eval。这个逻辑在 `analyze_functional_ablation.py` 和 `svd_utils.py` 的重构函数里。

**4.2 delta_loss**

$$\Delta \text{loss} = \text{loss}_{\text{ablation}} - \text{loss}_{\text{full}}$$

含义：如果删掉后 loss 明显上升，说明被删成分功能上重要。

代码指标名：`delta_loss`。

**4.3 delta_ppl**

$$\Delta \text{ppl} = \text{ppl}_{\text{ablation}} - \text{ppl}_{\text{full}}$$

代码指标名：`delta_ppl`。

**4.4 delta_task_metric**

如果有任务指标，例如 rouge（鲁棒指标/文本任务指标）或 accuracy（准确率）：

$$\Delta \text{task\_metric} = \text{metric}_{\text{ablation}} - \text{metric}_{\text{full}}$$

代码指标名：`delta_task_metric`。

**4.5 removed_fro_norm / normalized_damage**

脚本还会记录删除了多少 Frobenius norm（弗罗贝尼乌斯范数）：

- `removed_fro_norm`
    
- `removed_fro_fraction`
    

并计算：

$$\text{normalized\_damage} = \frac{\Delta \text{loss}}{\text{removed\_fro\_fraction}}$$

含义：不是简单看“删得多伤得大”，而是看“单位删除比例造成多大伤害”。

代码指标名：`normalized_damage`。

## 四、三类实验分别在做什么

下面把三个脚本再按“目的—公式—输出”串一下。

#### Module A：direction-level conflict profiling（方向级冲突剖析）

**目的**

找出哪些方向同时具有：高稳定性、高 client specificity（客户端特异性）、高冲突、高 pairwise fragility（两两平均脆弱性）。

**用到的公式**

核心就是前面这几项：

same_presence

$$\left|\frac{u_k^\top B_{\text{same}} v_k}{\sigma_k}\right|$$

diff_presence

$$\frac{1}{C-1}\sum_{c'\neq c}\left|\frac{u_k^\top B_{c'} v_k}{\sigma_k}\right|$$

pls_dir

$$\text{same\_presence} - \text{diff\_presence}$$

signed_conflict

$$\frac{1}{C-1}\sum_{c'\neq c}\max\left(0, -\frac{u_k^\top B_{c'}v_k}{\sigma_k}\right)$$

pairwise_retention_under_avg

$$\frac{1}{C-1}\sum_{c'\neq c} \left|0.5\cdot\left(1+\frac{u_k^\top B_{c'}v_k}{\sigma_k}\right)\right|$$

fragility_pair

$$1 - \text{pairwise\_retention\_under\_avg}$$

**输出**

主要是每个 direction 的分析表，例如：

- same_presence
    
- diff_presence
    
- pls_dir
    
- signed_conflict
    
- mean_signed_projection
    
- pairwise_retention_under_avg
    
- fragility_pair
    
    还有按 band / layer 的 summary（汇总）。
    

#### Module B：functional ablation（功能消融）

**目的**

验证哪些 band / directions 是功能上重要的。也就是：不只是“结构上像 personalization”，而是真的“删了会伤本地性能”。

**用到的公式**

先根据 band 或 selector 选出集合 $S$，然后：

remove:

$$B' = \sum_{k\notin S}\sigma_k u_k v_k^\top$$

keep-only:

$$B' = \sum_{k\in S}\sigma_k u_k v_k^\top$$

然后比较：

delta_loss

$$\text{loss}_{\text{ablation}} - \text{loss}_{\text{full}}$$

delta_ppl

$$\text{ppl}_{\text{ablation}} - \text{ppl}_{\text{full}}$$

delta_task_metric

$$\text{metric}_{\text{ablation}} - \text{metric}_{\text{full}}$$

normalized_damage

$$\frac{\Delta \text{loss}}{\text{removed\_fro\_fraction}}$$

**输出**

一个 ablation 结果表，告诉你：删的是哪一类 band / 哪一组 directions；删了多少；本地 loss / ppl / 任务指标变了多少。

#### Module C：same-round pre/post aggregation fragility（同轮聚合前后脆弱性）

**目的**

直接验证：本地有的方向，在服务器聚合后是不是被削弱了？

**用到的公式**

reference 方向来自 pre-agg local checkpoint：

retain_after_agg

$$\left| \frac{u_k^\top B_{\text{global post}} v_k}{\sigma_k} \right|$$

fragility_after_agg

$$1 - \text{retain\_after\_agg}$$

然后把它和 Module A 的结构分数连起来看，比如：

- signed_conflict vs retain_after_agg
    
- pls_dir vs retain_after_agg
    
- fragility_pair vs fragility_after_agg
    

**输出**

每个 direction 的聚合后保留率，以及和前面结构指标的关联结果。

## 五、把整个实验流程理顺

下面是最重要的“全流程图”。

**第一步：Module A 先做结构筛查**

你先在 local checkpoints 上，对每个 direction 算：

- same_presence
    
- diff_presence
    
- pls_dir
    
- signed_conflict
    
- pairwise_retention_under_avg
    
- fragility_pair
    

这一步回答：哪些方向像稳定的 personalization？哪些方向更容易和其他 client 冲突？哪些方向在平均时更容易丢失？

所以 A 的角色是：**结构证据 + 干扰机制线索**。

**第二步：Module B 做功能验证**

然后你拿 A 的结果来挑方向：

- 高 pls_dir 的方向
    
- 高 signed_conflict 的方向
    
- 高 fragility_pair 的方向
    
- 或 band（head / middle / tail / floor）
    

再做 remove / keep-only ablation，测：

- delta_loss
    
- delta_ppl
    
- delta_task_metric
    
- normalized_damage
    

这一步回答：这些结构上“可疑”的方向，功能上到底重不重要？

所以 B 的角色是：**功能证据**。

**第三步：Module C 做真实聚合验证**

最后，在 same-round pre/post aggregation 上算：

- retain_after_agg
    
- fragility_after_agg
    

并与 A 里的 pls_dir, signed_conflict, fragility_pair 做关联。

这一步回答：那些结构上更 client-specific、冲突更强、pairwise 更脆弱的方向，在真实 FedAvg 之后，是不是也真的更容易消失？

所以 C 的角色是：**聚合伤害证据**。

## 六、最后把四类分数放回你的研究问题

你现在其实已经有了一条非常清晰的研究链：

1. **stability / specificity**
    
    用 same_presence, diff_presence, pls_dir 来定义“它像不像稳定的 client-specific knowledge（客户端特异知识）”。
    
2. **conflict**
    
    用 signed_conflict, mean_signed_projection 来定义“它会不会和其他 client 打架”。
    
3. **fragility**
    
    用 pairwise_retention_under_avg, fragility_pair, retain_after_agg, fragility_after_agg 来定义“它会不会在平均 / 聚合后丢失”。
    
4. **functional importance**
    
    用 delta_loss, delta_ppl, delta_task_metric, normalized_damage 来定义“它删掉后会不会伤本地能力”。
    

所以你最终要找的，不是“tail 一定重要”，而是：

**那些 PLS 高（稳定且更 client-specific）、signed_conflict 高（跨 client 冲突强）、fragility 高（平均或聚合后容易丢）、delta_loss 高（删掉会伤本地性能）的 directions / subspaces（方向 / 小子空间）。**

这才是“值得保护的 personalization（个性化知识）”。
