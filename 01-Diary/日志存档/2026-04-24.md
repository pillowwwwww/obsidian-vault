============================================================
项目背景
============================================================

本项目研究 Federated Learning + LoRA 微调中的客户端个性化退化问题，项目代号 FedDGC。

基础模型主要是 LLaMA-1B，数据主要使用 SuperNI 指令任务。核心代码在：

Subspace_LoRA/

核心研究问题：
在任务异构 FL 场景中，FedAvg 聚合 LoRA A/B 因子后，会稀释客户端本地 ΔW = scaling * B @ A 中的 tail/floor spectral directions。这些 tail/floor directions 在 motivation 中被证明具有客户端特异性和功能价值。客户端每轮收到新的 global LoRA 后，需要反复重新恢复这些方向，造成 personalization adaptation 成本。

请先阅读以下两个文档，确保理解当前方法定义和实验语境：

1. Subspace_LoRA/plan/motivation_最终版.md

核心结论：
- FedAvg 对 ΔW 的 tail/floor directions 存在更强相对稀释。
- tail/floor directions 更客户端特异。
- local training 会恢复这些 directions，说明它们不是纯噪声，而是功能相关方向。
- 注意：实际 FedAvg 是分别聚合 LoRA A 和 B，因此 ΔW_global = B_global @ A_global，不等于 Σ p_c ΔW_c。
- 不要在代码、注释或实验解释中使用错误的线性 leave-self-out 推导。

2. Subspace_LoRA/plan/FedDGC_B_METHOD.md

当前方法定义是 FedDGC v9：
- 方法对象是 ΔW = scaling * B @ A，而不是单独的 LoRA-B。
- FedDGC-v9 是 client-private personalization plugin，不是新的 aggregation optimizer。
- 核心机制是 tail-restricted frozen bypass：
  C_{c,l} = Σ_{i in tail/floor} δ_i u_i v_i^T
- δ_i 是 observed dilution gap：
  α_i = <ΔW_global_eff, u_i v_i^T>
  δ_i = max(0, σ_i - max(α_i, 0))
- C 不写回 LoRA 参数，不上传服务器，而是在客户端本地 forward 中作为 frozen bypass：
  y = W_base x + s_l BAx + m_c λ_{c,l} C_{c,l}x
- 当前正式版本使用 per-layer norm calibration：
  λ_{c,l} = η * ||s_l B_l A_l||_F / (||C_{c,l}||_F + eps)
  因此 η = ||λC||_F / ||sBA||_F，是 bypass 修正相对 LoRA 更新的强度。
- 旧的 raw λ=512/1024 只是 legacy diagnostic，不应作为正式方法解释。
- gate 是客户端本地一小批数据判断 bypass 是否启用：
  如果 L_bypass < L_global，则启用 bypass；否则使用 clean LoRA forward。
- 上传服务器的始终是 clean LoRA A/B，bypass 不进入上传路径，避免污染全局模型。

Baseline 1: Local-only LoRA
============================================================

目的：
no-federation personalization reference。用于回答：在任务异构下，每个客户端自己训练 LoRA 是否已经足够，联邦共享是否有帮助。

注意：
Local-only LoRA 不是理论 upper bound。不要在代码注释或实验说明中称为 upper bound。它是 no-federation personalization reference。

实现方式：
- 每个 client 维护自己的 LoRA 参数。
- 不进行服务器聚合。
- 不上传。
- 不广播 global LoRA。
- 为了公平，尽量复用 FedAvg 的 client sampling schedule：
  - 当某个 client 在 FL schedule 中会被选中时，就训练该 client 自己的 local LoRA。

  - 这样 local-only 的每个 client 训练预算和 FedAvg 中该 client 的参与次数一致。
- 如果现有框架不方便复用 participation schedule，请实现 compute-matched 模式：
  - 每个 client local training 的 epoch 数约等于 FedAvg 中该 client 的实际参与次数 × local_epoch。
  - 记录具体实现方式到 README 或实验日志中。
- 评估每个 client 自己的 local LoRA。

需要支持：
- 使用相同 client_subset_seed=42。
- 支持 run_seed ∈ {42,43,44}。
- 支持 participation =0.10。
- learning_rate =1e-2。

smoke test 要求：
- 至少 1-2 rounds 或等价本地训练预算。
- 至少 1 个 participation ratio、1 个 lr、1 个 run_seed。
- 确认每个 client 的 private LoRA state 可以正确保存/加载/评估。

Baseline 2: Ditto-LoRA
============================================================

目的：
PFL baseline。Ditto 本身是经典 personalized FL 方法，你需要搜索ditto的算法实现逻辑，你可以参考https://github.com/TsingZ0/PFLlib/blob/master/system/flcore/clients/clientditto.py和https://github.com/TsingZ0/PFLlib/blob/master/system/flcore/servers/serverditto.py。然后把该算法集成到我们框架下的baseline/文件夹下面。
Ditto-LoRA 是我们在 LoRA 参数空间中的适配版本，你需要把Ditto的算法适配到lora下，命名为Ditto-LoRA。

请实现一个 LoRA-space Ditto adaptation。

建议定义：
- 服务器维护 global LoRA 参数 θ_global = {A_l, B_l}。
- 每个 client 维护 private personalized LoRA 参数 θ_c^p。
- global branch：
  - 参与 FedAvg 的 clean LoRA，按普通 FedAvg-LoRA 训练和上传。
- personalized branch：
  - 每个 client 本地维护，不上传。
  - 训练目标为：
    L_c(θ_c^p) + μ / 2 * ||θ_c^p - θ_global||_2^2
  - 正则项只作用于 trainable LoRA 参数，不作用于 base model。
- 每轮 selected client：
  - 从服务器接收 θ_global。
  - 训练 global branch，用于上传聚合。
  - 同时或随后更新该 client 的 θ_c^p，用于 personalized eval。
- 非 selected client：
  - 保留自己的 θ_c^p。
- 首次出现的 client：
  - θ_c^p 可以初始化为当前 θ_global。
- personalized eval：
  - 使用 θ_c^p。
- clean global eval：
  - 使用 θ_global。

需要支持/记录的超参数：
- μ，建议初始候选：0.01, 0.1, 1.0。
- 本轮先实现 μ configurable，默认 smoke test 使用 μ=0.1。
- local personalized update steps 默认与 local epoch 对齐。
- 明确记录 private LoRA 参数是否持久化在 client state 中。

smoke test 要求：
- 至少 1-2 rounds。
- 至少 1 个 participation ratio、1 个 lr、1 个 run_seed、μ=0.1。
- 确认 global branch 可以上传聚合。
- 确认 private branch 不上传。
- 确认 personalized eval 使用 θ_c^p。
- 确认 clean global eval 使用 θ_global。

需要保存：
- Avg Personalized Loss using θ_c^p
- Worst Client Loss
- P90 Client Loss
- Clean Global Loss using θ_global
- μ
- private parameter count
- uploaded parameter count
- communication cost：应与 FedAvg-LoRA 近似一致，因为 private LoRA 不上传
