# FedDGC v9 Method



## 1. Method Position

  

FedDGC v9 is a **client-private personalization plugin** for federated LoRA fine-tuning under task heterogeneity.

  

The shared FL training protocol remains standard factor FedAvg:

  

```text

server aggregates LoRA A/B factors

clients upload only clean trainable LoRA factors

FedDGC correction stays private on each client

```

  

FedDGC acts only on the effective LoRA update:

  

$$

\Delta W_l = s_l B_l A_l,

$$

  

where \(s_l=\alpha_l/r_l\) is the LoRA scaling for layer \(l\).

  

The v9 claim is intentionally narrow:

  

> FedDGC protects client-specific tail/floor directions with a private frozen bypass, reducing repeated personalized recovery cost without sending the correction to the server.

  

FedDGC v9 no longer claims that fragility ranking is the main source of improvement. Current SuperNI-50 evidence shows that the energy budget is usually inactive, so ranking often does not change the selected tail/floor set. The supported mechanism is:

  

```text

which directions: tail/floor singular directions

how much to restore: observable dilution gap delta_i

where it lives: private frozen bypass, never uploaded

```

  

---

  

## 2. Why FedDGC Operates on Delta W

  

In the actual FL protocol, the server separately averages LoRA factors:

  

$$

A_l^{t,\mathrm{glob}}

=

\sum_{j\in S_t}p_j A_{j,l}^{t,\mathrm{upload}},

\qquad

B_l^{t,\mathrm{glob}}

=

\sum_{j\in S_t}p_j B_{j,l}^{t,\mathrm{upload}},

\qquad

\sum_{j\in S_t}p_j=1.

$$

  

Therefore the shared effective update is:

  

$$

\Delta W_l^{t,\mathrm{glob}}

=

s_l B_l^{t,\mathrm{glob}} A_l^{t,\mathrm{glob}},

$$

  

and generally:

  

$$

s_l B_l^{t,\mathrm{glob}} A_l^{t,\mathrm{glob}}

\neq

\sum_{j\in S_t} p_j\, s_l B_{j,l}^{t,\mathrm{upload}} A_{j,l}^{t,\mathrm{upload}}.

$$

  

This is why FedDGC is defined in \(\Delta W\)-space rather than on LoRA-B alone.

  

The old leave-self-out formula

  

$$

\alpha_i = p_c\sigma_i + (1-p_c)\beta_i

$$

  

is not valid for online selection under factor FedAvg, because \(B\) and \(A\) are averaged before multiplication. FedDGC v9 therefore uses only observable global retention.

## 3. Client-Private Local Directions

  

After client \(c\) finishes local training in round \(t\), FedDGC builds a local spectral pack from the client effective personalized update.

  

In the current online implementation, if a bypass was active in the current round, the pack includes the active bypass:

  

$$

\widetilde{\Delta W}_{c,l}^{t}

=

s_l B_{c,l}^{t,\mathrm{train}} A_{c,l}^{t,\mathrm{train}}

+

m_c^t \lambda_{c,l}^{t-1} C_{c,l}^{t-1}.

$$

  

Here:

  

- \(A_{c,l}^{t,\mathrm{train}},B_{c,l}^{t,\mathrm{train}}\) are the clean trainable LoRA factors after local training.

- \(C_{c,l}^{t-1}\) is the private cache from the previous participation of the same client.

- \(m_c^t\in\{0,1\}\) indicates whether the bypass was enabled in this round.

- This effective update is used only for **private cache construction**.

- The server still receives only clean LoRA factors.

  

This design preserves the effective personalized model used by the client. It also means that old private memory can persist across participations. For a clean-pack ablation, build the pack only from \(s_l B_{\mathrm{train}}A_{\mathrm{train}}\).

  

FedDGC computes an SVD:

  

$$

\widetilde{\Delta W}_{c,l}^{t}

=

\sum_i

\sigma_{c,l,i}^{t}

u_{c,l,i}^{t}

(v_{c,l,i}^{t})^\top.

$$

  

Each unit direction atom is:

  

$$

\phi_{c,l,i}^{t}

=

u_{c,l,i}^{t}(v_{c,l,i}^{t})^\top,

\qquad

\|\phi_{c,l,i}^{t}\|_F=1.

$$

  

Implementation note: `collect_local_pack` computes these directions with low-rank algebra and stores \(\sigma_i,u_i,v_i^\top\) rather than dense correction matrices.

  

---

  

## 4. Observable Global Retention

  

For each client direction \(\phi_i=u_iv_i^\top\), FedDGC measures how much of that direction is retained by the current clean global LoRA update:

  

$$

\alpha_i

=

\langle

\Delta W_l^{t,\mathrm{glob}},

\phi_i

\rangle_F.

$$

  

The implementation avoids dense \(\Delta W_l^{t,\mathrm{glob}}\) materialization:

  

$$

\alpha_i

=

s_l\,u_i^\top

\left[

B_l^{t,\mathrm{glob}}

\left(

A_l^{t,\mathrm{glob}}v_i

\right)

\right].

$$

  

Only same-direction positive retention is counted:

  

$$

\alpha_i^+ = \max(\alpha_i,0).

$$

  

The dilution gap is:

  

$$

\delta_i

=

\max(0,\sigma_i-\alpha_i^+).

$$

  

\(\delta_i\) is the amplitude stored in the cache. It is the observable amount of client signal missing from the clean global model along direction \(\phi_i\).

  

---

  

## 5. Tail-Restricted Direction Set

  

The motivation establishes that tail/floor directions are more client-specific and more strongly diluted in relative terms. FedDGC v9 therefore restricts correction to tail/floor directions.

  

For each layer, define a numerical singular-value floor:

  

$$

\tau_l

=

\epsilon_{\mathrm{rank}}\sigma_{l,\max},

\qquad

\epsilon_{\mathrm{rank}}=10^{-4}.

$$

  

For a direction index \(i\in\{0,\ldots,r_l-1\}\), define its layerwise spectral quantile:

  

$$

q_i = \frac{i}{r_l}.

$$

  

Eligibility:

  

```text

delta_i > 0

sigma_i >= tau_l

q_i >= q_tail

```

  

Default SuperNI-50 experiments use:

  

```text

q_tail = 0.6

```

  

With LoRA rank \(r=32\), this keeps indices \(20,\ldots,31\), i.e. the deepest 12 directions per LoRA-updated layer.

  

The private correction cache is:

  

$$

C_{c,l}^{t}

=

\sum_{i\in I_{c,l}^{t}}

\delta_i u_i v_i^\top,

$$

  

where \(I_{c,l}^{t}\) is the selected eligible tail/floor set.

## 6. Safety Budget

  

FedDGC v9 retains an energy budget only as a guardrail:

  

$$

g_i

=

\frac{\delta_i^2}{E_c},

\qquad

E_c

=

\sum_{\text{LoRA-updated layers }l}

\sum_j \sigma_{c,l,j}^2

+\epsilon.

$$

  

“LoRA-updated layers” means the layers that carry trainable LoRA factors in the current run. In the default LLaMA-1B setup:

  

```text

q_proj, k_proj, v_proj, o_proj, gate_proj, down_proj, up_proj

```

  

Selection rule:

  

```text

if sum eligible g_i <= rho_max:

    select all eligible tail/floor directions

else:

    sort by delta_i / max(sigma_i, tau_l)

    greedily keep a prefix under rho_max

```

  

Current SuperNI-50 runs usually satisfy:

  

```text

sum eligible g_i << rho_max

```

  

so the budget rarely triggers. This is not a failure of v9; the budget is a safety cap, not the main selection mechanism.

## 7. Frozen Bypass Injection

  

At a later participation round, client \(c\) receives clean global LoRA factors \((A_l,B_l)\). If a cache exists and passes the gate, FedDGC registers a frozen forward bypass:

  

$$

y

=

W_{\mathrm{base}}x

+

s_l B_lA_lx

+

\lambda_{c,l} C_{c,l}x.

$$

  

FedDGC does **not** refactorize \(\Delta W+\lambda C\) into LoRA parameters.

  

Runtime semantics:

  

- \(A_l,B_l\) are trainable.

- \(C_{c,l}\) is frozen.

- \(C_{c,l}\) is not in the optimizer.

- \(C_{c,l}\) is not written into LoRA state dicts.

- \(C_{c,l}\) is not uploaded.

- Gradients still flow through the layer input \(x\); only correction tensors are frozen.

  

The low-rank bypass is computed as:

  

$$

C_{c,l}x

=

U_{\mathrm{sel}}

\left[

\mathrm{diag}(\delta)

\left(

V_{\mathrm{sel}}^\top x

\right)

\right].

$$

  

---

  

## 8. Eta-Calibrated Strength

  

FedDGC v9 uses a relative norm target \(\eta\), replacing the earlier raw scalar \(\lambda\).

  

The intended ratio is:

  

$$

\eta

=

\frac{\|\lambda_{c,l}C_{c,l}\|_F}

{\|s_l B_lA_l\|_F+\epsilon}.

$$

  

Thus each client-layer uses:

  

$$

\lambda_{c,l}

=

\eta

\frac{\|s_l B_lA_l\|_F}

{\|C_{c,l}\|_F+\epsilon}.

$$

  

The implementation logs:

  

```text

lambda_effective

raw_cache_norm_ratio = ||C||_F / ||sBA||_F

bypass_norm_ratio = ||lambda_effective C||_F / ||sBA||_F

```

  

When \(\eta>0\), the raw CLI argument `feddgc_lambda` is a legacy fallback and should not be interpreted as the active strength.

## 9. One-Batch Gate

  

Because a client cache may be stale, FedDGC can evaluate a small local training batch before enabling the bypass:

  

$$

L_{\mathrm{glob}}

=

\mathcal{L}(G_t;\mathcal{B}_{\mathrm{gate}}),

\qquad

L_{\mathrm{bypass}}

=

\mathcal{L}(G_t+\lambda C_c;\mathcal{B}_{\mathrm{gate}}).

$$

  

Gate rule:

  

$$

m_c^t

=

\mathbf{1}

\left[

L_{\mathrm{bypass}} < L_{\mathrm{glob}}

\right].

$$

  

Implementation details:

  

- `feddgc_gate_enabled=True` enables this test.

- `feddgc_gate_batch_size=0` means use `local_micro_batch_size`.

- The gate uses local training data, not test data.

- If the gate fails, the client trains and evaluates with standard LoRA for that round.

## 10. Training, Evaluation, and Upload

  

### Local Training

  

If the bypass is enabled:

  

$$

y

=

W_{\mathrm{base}}x

+

s_lB_lA_lx

+

\lambda_{c,l}C_{c,l}x.

$$

  

Only \(A_l,B_l\) are optimized.

  

If the bypass is disabled:

  

$$

y

=

W_{\mathrm{base}}x

+

s_lB_lA_lx.

$$

  

### Personalized Evaluation

  

The personalized evaluation uses the same bypass state as local training:

  

- bypass enabled: evaluate clean trained LoRA plus frozen private bypass

- bypass disabled: evaluate clean trained LoRA only

  

### Upload

  

The server receives:

  

$$

(A_{c,l}^{t,\mathrm{upload}},B_{c,l}^{t,\mathrm{upload}})

=

(A_{c,l}^{t,\mathrm{train}},B_{c,l}^{t,\mathrm{train}}).

$$

  

There is:

  

```text

no parameter injection

no upload-time SVD

no residual subtraction

no correction upload

```

## 11. Online Algorithm

  

For each communication round \(t\):

  

1. Server sends clean global LoRA factors.

2. Selected client loads its private FedDGC cache, if available.

3. Client optionally runs the one-batch gate.

4. Client trains LoRA factors with or without frozen bypass.

5. Client evaluates personalized performance under the same bypass state.

6. Client uploads only clean trained LoRA factors.

7. Server applies standard factor FedAvg.

8. Client builds a local spectral pack from its effective personalized update.

9. FedDGC computes \(\sigma_i,\alpha_i,\delta_i\).

10. FedDGC selects eligible tail/floor diluted directions.

11. Selected sparse atoms become the next private cache.

## 13. What v9 Removes

  

FedDGC v9 does not use:

  

- LoRA-B-only correction

- refactorizing \(\Delta W+\lambda C\) into LoRA parameters

- upload-time correction subtraction

- upload-time SVD

- online leave-self-out \(\beta\)

- the invalid online decomposition \(\alpha_i=p_c\sigma_i+(1-p_c)\beta_i\)

- `tau_g`

- `kappa`

- `gamma`

- `c_hard`

- `eta_conf`

- warm/cold lambda

- soft conflict penalty

- fragility ranking as a claimed source of gain under the current budget regime

## 14. Paper Explanation Notes

  

### 14.1 Why Tail/Floor Only?

  

The motivation shows that tail/floor directions have stronger relative dilution and stronger client specificity. FedDGC v9 directly operationalizes this evidence by correcting only tail/floor directions.

  

### 14.2 Is the Correction Just Noise?

  

No. The direction set is tail/floor, but the amplitude is not arbitrary:

  

$$

C=\sum_i \delta_i u_iv_i^\top.

$$

  

The correction strength is determined by the observed missing coefficient \(\delta_i\). No-delta and random-tail ablations should test this claim.

  

### 14.3 Why Can Budget Utilization Be Tiny?

  

Tail/floor directions can have small absolute Frobenius energy even when their relative dilution is large. Therefore budget utilization can be far below `rho_max`. In v9, this means the safety cap is inactive; it does not invalidate the tail-restricted bypass.

  

### 14.4 Does FedDGC Sacrifice the Global Model?

  

FedDGC is a PFL method, so the primary target is personalized client performance. Still, clean global behavior must be monitored through:

  

```text

clean init loss

weighted init loss

worst-client loss

P90 loss

```

  

Because \(C_c\) is private and not uploaded, FedDGC should not directly contaminate the server aggregation path.

  

### 14.5 Why FedDGC May Not Add Much on FedEx-LoRA

  

FedEx-LoRA absorbs the exact aggregation residual into \(W_0\). If FedDGC is applied on top of FedEx, its retention coefficient \(\alpha_i\) should include the FedEx residual in the effective global update. Otherwise FedDGC may double-correct directions already restored by FedEx.

  

Thus:

  

```text

FedEx is a strong baseline.

FedEx + FedDGC may have marginal gain.

That outcome is expected, not necessarily a failure.

```

## 15. Recommended Ablations

  

Required:

  

- FedAvg vs FedDGC-v9

- random tail bypass

- no-delta tail bypass

- head/middle bypass

- no-bypass cache-only

- eta sweep around the chosen operating point

  

Strongly recommended:

  

- gate on/off

- clean-pack cache construction

- q-tail sensitivity

- recovery curve / AUC loss

- subgroup by cache age and client data size
