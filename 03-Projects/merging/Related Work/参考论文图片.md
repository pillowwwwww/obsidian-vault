## FedDcomp：参数分解

![[image-124.png]]

![[image-125.png]]


FedDecomp 的主线是“**显式解耦 general knowledge 和 personalized knowledge**”。它不是在共享模型上做事后补偿，而是从参数层面把每层写成“共享部分 + 个性化部分”的加法分解，并且让个性化部分保持低秩；再配合交替训练策略提升解耦效果。换句话说，FedDecomp 假设：**共享知识和个性化知识应该在参数结构里长期共存，但要被明确拆开。**

# LLM社区的论文

除去联邦部分，FedDGC 在大模型 NLP 社区里，我觉得最像下面几类工作。

**第一类：LoRA / PEFT model merging。**  
这是最像的一类。尤其像那些不是简单平均 LoRA，而是显式处理**低秩子空间对齐、方向保持、奇异结构**的方法。RobustMerge 本身当然是一个；另外像 **KnOTS** 这类工作，用 SVD 把不同 LoRA 更新投到更对齐的空间里再合并，核心也是“方向/子空间对齐比元素级平均更重要”；**Core Space Merging** 也属于这一谱系，它强调把 LoRA-aligned models 映到共享 low-rank core space 里合并，以尽量保住低秩信息。FedDGC 虽然不是“合并多个 LoRA expert”，但它同样在 `ΔW` 的低秩方向上做选择、重分配和再投影，所以从方法气质上非常接近这一类。([arXiv](https://arxiv.org/html/2502.17159v2?utm_source=chatgpt.com "RobustMerge: Parameter-Efficient Model Merging for ..."))

**第二类：奇异值/谱感知的 LoRA 工作。**  
FedDGC 很像那些认为“LoRA 的有效容量不只是 rank 数字，而取决于奇异值分布、重要方向和谱预算怎么分配”的工作。比如 **AdaLoRA** 用奇异值重要性做自适应 rank 分配；**PiSSA** 直接把 LoRA 初始化/更新和 principal singular values / vectors 联系起来；还有一些综述把这类方法归为 spectral-aware / SVD-parameterized LoRA。FedDGC 和它们的共通点不在“都做联邦”，而在：**都把奇异值和奇异方向当成方法设计的一等公民**，而不是把 LoRA 仅仅视为两个小矩阵。区别是，AdaLoRA/PiSSA 更偏单模型 PEFT 优化或初始化，FedDGC 更偏“训练后观测哪些方向被压掉，再做缺口恢复”。([arXiv](https://arxiv.org/html/2501.00365v1?utm_source=chatgpt.com "Low-Rank Adaptation for Foundation Models"))

**第三类：能力保留 / 合并前后知识保真的 LoRA 组合工作。**  
像 **LoRA-LEGO** 这类把 LoRA 分解成更小“semantic units”再重组的方向，也和 FedDGC 有相似气质：都不是粗暴平均，而是承认 LoRA 内部有更细粒度的可组合结构，需要按单元/方向去保留关键知识。再比如一些 continual merging 工作会强调“merge before forget”，本质上和 FedDGC 的 capability retention 直觉很近：不要让已有能力在整合过程中被洗掉。FedDGC 的表达更谱化，LoRA-LEGO/continual merging 更模块化，但底层直觉相通。([OpenReview](https://openreview.net/forum?id=j6fsbpAllN&utm_source=chatgpt.com "Merging LoRAs like Playing LEGO: Pushing the Modularity ..."))

更具体点，最接近的参照系依次是：

**RobustMerge → KnOTS / Core Space Merging → AdaLoRA / PiSSA → LoRA-LEGO / continual LoRA merging。**  
其中前两类最像它的方法外形，后两类最像它的谱结构直觉。([arXiv](https://arxiv.org/html/2502.17159v2?utm_source=chatgpt.com "RobustMerge: Parameter-Efficient Model Merging for ..."))
