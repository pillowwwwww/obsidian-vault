# 监督式 KD 与 On-policy KD 笔记

## 1. 核心区别

一句话：

- **监督式 KD**：在标准答案路径上，让学生模仿教师。
- **On-policy KD**：在学生自己生成的路径上，让学生模仿教师。

核心差别不是“谁给监督信号”，而是：

> 训练时的上下文来自哪里？

| 方法 | 上下文来源 | 监督信号来源 | 主要优点 | 主要问题 |
|---|---|---|---|---|
| 监督式 KD | 标准答案 | 教师模型 | 稳定，样本质量高 | 训练和推理分布不一致 |
| On-policy KD | 学生自己生成的答案 | 教师模型 | 更接近真实推理过程 | 学生生成差时，训练样本质量低 |

---

## 2. 监督式 KD 是什么？

监督式 KD 使用数据集中的标准答案作为训练路径。

假设任务是翻译：

```text
输入：翻译：我喜欢机器学习。
标准答案：I like machine learning.

把标准答案切成 token：
	I / like / machine / learning / .
```

训练时，模型不是自由生成整句话，而是使用标准答案前缀来预测下一个 token。

例如：

|训练位置|给模型看的上下文|要学习的下一个 token|
|---|---|---|
|1|翻译：我喜欢机器学习。|I|
|2|翻译：我喜欢机器学习。 I|like|
|3|翻译：我喜欢机器学习。 I like|machine|
|4|翻译：我喜欢机器学习。 I like machine|learning|
|5|翻译：我喜欢机器学习。 I like machine learning|.|

这里的上下文来自标准答案，所以叫：

```text
答案路径作为上下文
```

---

## 3. 监督式 KD 的训练流程

以第 4 个位置为例。

当前上下文是：

```text
翻译：我喜欢机器学习。 I like machine
```

### Step 1：教师输出概率分布

教师模型看到这个上下文后，给出下一个 token 的概率：

|token|教师概率|
|---|--:|
|learning|0.82|
|translation|0.04|
|intelligence|0.03|
|learn|0.02|
|其他|0.09|

### Step 2：学生输出概率分布

学生模型看到同样的上下文，也输出概率：

|token|学生概率|
|---|--:|
|learning|0.35|
|translation|0.20|
|learn|0.15|
|model|0.10|
|其他|0.20|

### Step 3：训练学生模仿教师

训练目标是让学生分布接近教师分布：

```text
让学生提高 learning 的概率
让学生降低 learn、translation 等不合适 token 的概率
```

所以监督式 KD 不是只学一个正确 token，而是学习教师对整个词表的概率判断。

---

## 4. 为什么监督式 KD 会有推理 mismatch？

因为训练时和推理时的上下文不同。

### 训练时

学生看到的是标准答案前缀：

```text
I like machine
```

它学习：

```text
在 I like machine 后面，应该生成 learning
```

### 推理时

学生需要自己一步一步生成。

如果它前面生成错了，例如：

```text
I like machinery
```

那么下一步的上下文变成：

```text
I like machinery
```

这个上下文不是标准答案路径，训练时可能很少见。

所以问题不是“学生没有学每个 token 的概率”。

问题是：

```text
监督式 KD 学的是：
p(下一个 token | 标准答案前缀)

推理时需要的是：
p(下一个 token | 学生自己生成的前缀)
```

上下文变了，模型的预测分布也会变。

---

## 5. On-policy KD 是什么？

On-policy KD 先让学生自己生成答案，然后让教师在学生生成的路径上给监督信号。

还是翻译任务：

```text
输入：翻译：我喜欢机器学习。
```

学生自己生成了：

```text
I like machine learn .
```

这条路径虽然有错误，但它是真实推理时学生可能走到的路径。

On-policy KD 会在这条学生路径上训练：

|训练位置|给模型看的上下文|教师给反馈|
|---|---|---|
|1|翻译：我喜欢机器学习。|教第一个 token 怎么生成|
|2|翻译：我喜欢机器学习。 I|教 I 后面怎么生成|
|3|翻译：我喜欢机器学习。 I like|教 I like 后面怎么生成|
|4|翻译：我喜欢机器学习。 I like machine|教 machine 后面怎么生成|
|5|翻译：我喜欢机器学习。 I like machine learn|教错误前缀后面怎么继续|

---

## 6. On-policy KD 为什么能学到“修正”？

这里的“修正”不是直接修改已经生成的旧 token。

它修正的是模型参数，让学生以后：

1. 更少犯同样的错误；
    
2. 已经进入错误状态时，也更知道如何继续。
    

---

## 7. On-policy KD 的两类学习信号

假设学生生成了错误句子：

```text
I like machine learn .
```

错误 token 是：

```text
learn
```

正确 token 更可能是：

```text
learning
```

### 7.1 错误发生前：学会以后少犯错

在生成 `learn` 之前，前缀是：

```text
I like machine
```

教师在这个前缀下可能给出：

|token|教师概率|
|---|--:|
|learning|0.82|
|learn|0.02|
|translation|0.04|
|其他|0.12|

学生会学习：

```text
下次看到 I like machine 时，
不要高概率生成 learn，
而要更倾向生成 learning。
```

这叫：

```text
在错误发生前纠偏
```

---

### 7.2 错误发生后：学会从错误状态继续

错误已经发生后，前缀变成：

```text
I like machine learn
```

教师会在这个错误前缀下继续给出下一步分布。

例如教师可能认为：

|token|教师概率|
|---|--:|
|ing|0.45|
|.|0.20|
|about|0.08|
|其他|0.27|

学生会学习：

```text
如果我已经生成到了 I like machine learn，
下一步应该怎样继续才相对合理。
```

这叫：

```text
在错误状态下学习恢复
```

---

## 8. 再举一个问答例子

任务：

```text
Q: The capital of France is?
A:
```

正确答案：

```text
Paris.
```

学生 on-policy 生成：

```text
London is
```

### 位置 1：错误发生前

上下文：

```text
Q: The capital of France is?
A:
```

教师分布可能是：

|token|教师概率|
|---|--:|
|Paris|0.95|
|London|0.01|
|Berlin|0.01|

学生之前生成了 `London`，说明它在这个位置错了。

训练后，学生会：

```text
提高 Paris 的概率
降低 London 的概率
```

### 位置 2：错误发生后

上下文已经变成：

```text
Q: The capital of France is?
A: London
```

教师不能回头改掉 `London`。

但它可以告诉学生下一步如何继续，例如：

```text
London is not correct; Paris is the capital of France.
```

所以学生可以学习：

```text
已经生成错误内容后，如何继续生成更合理的内容。
```

---

## 9. 二者流程对比

### 监督式 KD

```text
输入 prompt
    ↓
使用标准答案前缀作为上下文
    ↓
教师在标准前缀上输出 soft label
    ↓
学生在同样前缀上输出分布
    ↓
训练学生分布接近教师分布
```

特点：

```text
训练路径干净、稳定，但和学生真实推理路径不完全一致。
```

---

### On-policy KD

```text
输入 prompt
    ↓
学生先自己生成答案
    ↓
使用学生生成的前缀作为上下文
    ↓
教师在学生前缀上输出 soft label
    ↓
学生在同样前缀上输出分布
    ↓
训练学生分布接近教师分布
```

特点：

```text
训练路径更接近学生真实推理过程，但学生生成太差时，训练样本质量可能较低。
```

---

## 10. 最重要的理解

监督式 KD 的核心问题：

```text
训练时，学生总是在正确前缀上学习；
推理时，学生必须在自己生成的前缀上继续。
```

On-policy KD 的核心改进：

```text
训练时就让学生暴露在自己生成的前缀上，
因此更接近真实推理状态。
```

但 On-policy KD 的风险是：

```text
如果学生太弱，生成路径质量很差，
教师在这些奇怪上下文上的反馈也可能不稳定。
```

---

## 11. 一句话总结

```text
监督式 KD：老师拿标准答案前缀教学生。
On-policy KD：学生先自己写，老师再沿着学生写出的路径教它。
```


# RL

## 1. 什么是“推理模型”？

**推理模型 reasoning model** 不是指一种固定网络结构，而是指一种经过专门训练、在回答前会生成较长思考过程的 LLM。

它通常有几个特征：

第一，模型会生成较长的 **Chain-of-Thought / long CoT**。  
也就是先分析、尝试、反思、验证，再给最终答案。

第二，它常用于数学、代码、STEM、逻辑题、复杂规划等任务。  
这些任务的特点是：最终答案可以验证，但中间推理过程很长。

第三，它经常使用 **test-time scaling**。  
也就是推理时愿意花更多 token、更长时间思考，难题生成更长推理，简单题生成较短推理。DeepSeek-R1 的 Nature 文章明确提到 R1-Zero 会随着 RL 训练逐渐增加 thinking time，并出现反思、验证、策略调整等推理行为


## 2. 什么是 RLVR？

**RLVR = Reinforcement Learning with Verifiable Rewards**，中文可译为：

> **基于可验证奖励的强化学习**

它和 RLHF 的区别很重要。

RLHF 通常依赖人类偏好或奖励模型，比如“哪个回答更好”。  
RLVR 则依赖可以自动验证的奖励，比如：

数学题答案是否正确；  
代码是否通过单元测试；  
格式是否符合要求；  
某个工具调用结果是否满足条件。

所以 RLVR 的奖励通常更“硬”：

> 答对 = 1，答错 = 0；  
> 或者通过测试 = 高奖励，未通过 = 低奖励。

和 OPD 的关系是：

> RLVR 给的是 **终局奖励**：最后答对没答对。  
> OPD 给的是 **token-level / process-level dense supervision**：学生每一步生成到哪里，教师就在那个前缀上给分布指导

**RLHF 更适合开放式对齐。**  
**RLVR 更适合数学、代码、逻辑、推理任务。**
## 3. 什么是“自蒸馏”？

普通蒸馏是：

> 大教师模型 teacher 教 小学生模型 student。

**自蒸馏 self-distillation** 是：

> 模型自己教自己，或者同一个模型在不同条件下分别扮演 teacher 和 student。

在 OPD 语境下，最典型的是 **On-Policy Self-Distillation, OPSD**。

它的核心做法是：

学生角色只看到题目，自己生成推理轨迹；  
教师角色看到更多信息，比如 verified reasoning trace、参考解、正确答案或 privileged information；  
然后在学生自己生成的轨迹上，让“有额外信息的自己”去指导“没额外信息的自己”。

这就保留了 OPD 的优点：

> 训练数据来自学生自己的 on-policy rollout。

同时又避免了传统 OPD 的一个缺点：

> 不再必须依赖一个更大的外部教师模型。

|方法|奖励来源|特点|
|---|---|---|
|RLHF|人类偏好或奖励模型|适合开放式聊天、写作、安全对齐|
|RLVR|自动验证器、规则、单元测试、标准答案|适合数学、代码、逻辑、STEM 推理|
# 4. 和 OPD 有什么关系？

你前面关心的是 **On-policy Distillation**。  
现在这些概念和 OPD 的关系是：

|方法|监督信号|特点|
|---|---|---|
|RLVR|最终答案奖励|稀疏，但不需要教师推理过程|
|GRPO|组内相对奖励|更省资源，适合大规模 RL|
|OPD|教师在学生轨迹上的 token-level 指导|信号更密集，但需要教师或自教师|
|自蒸馏 OPD|模型自己构造教师信号|减少外部教师依赖|

RLVR 像是：

> 模型做完整张卷子，最后告诉它“对了几题”。

OPD 像是：

> 模型做题过程中，老师一步步指出“这里下一步应该怎么走”。

所以在推理模型训练里，RLVR 和 OPD 是互补的：

**RLVR 擅长判断最终结果对不对。**  
**OPD 擅长指导中间推理过程怎么改。**

这也是为什么最近 OPD 会开始和推理模型、RLVR、自蒸馏结合：  
因为只靠最终 reward 训练推理过程，信号太稀疏；而 OPD 可以在模型自己的推理轨迹上提供更细粒度的过程监督。

## PPO 和 DPO 有什么区别？

最核心区别：

> **PPO 是强化学习算法；DPO 是偏好学习算法，不显式做 RL。**

举个例子。

假设一个 prompt 有两个回答：

```
Prompt: 请解释什么是联邦学习。回答 A：清晰、准确、安全。回答 B：含糊、错误较多。
```

人类标注或偏好数据告诉我们：

```
A 优于 B
```

**DPO** 的做法是：

> 直接调整模型，让它更偏向生成 A，减少生成 B 的概率。

它不需要先训练一个 reward model 来给 A、B 打分。

**PPO** 的做法更像：

> 先训练或使用一个 reward model，给模型生成的回答打分；然后用强化学习更新模型，让高 reward 回答概率上升，低 reward 回答概率下降。

所以可以这样记：

> **PPO：先有奖励，再用 RL 优化策略。**  
> **DPO：直接用偏好对优化模型，不显式走 reward model + RL 这条路。**

| 概念   | 英文全称                                           | 核心作用                  | 和推理的关系                 |
| ---- | ---------------------------------------------- | --------------------- | ---------------------- |
| RL   | Reinforcement Learning                         | 用奖励优化策略               | 总训练框架                  |
| RLHF | Reinforcement Learning from Human Feedback     | 用人类偏好对齐模型             | 让回答更符合人类偏好             |
| RLVR | Reinforcement Learning with Verifiable Rewards | 用可验证答案训练模型            | 最直接强化数学、代码、逻辑推理        |
| PPO  | Proximal Policy Optimization                   | 一种 RL 策略优化算法          | 可用于 RLHF / RLVR        |
| DPO  | Direct Preference Optimization                 | 直接从偏好对训练模型            | 常用于替代 RLHF 中复杂的 PPO 流程 |
| GRPO | Group Relative Policy Optimization             | 不用 critic 的组内相对 RL 优化 | 常用于推理模型的 RLVR 训练       |
