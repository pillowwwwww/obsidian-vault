
# 1. “答案路径作为上下文”到底是什么意思？

这其实就是语言模型训练里的 **teacher forcing**。

假设任务是翻译：

**输入 (x)：**

> 翻译：我喜欢机器学习。

标准答案 (y) 是：

> I like machine learning.

为了简化，我们把答案切成几个 token：

[  
y = [\text{I}, \text{like}, \text{machine}, \text{learning}, \text{.}]  
]

监督式 KD 训练时，不是让学生自己从头生成完整答案，而是把标准答案的前缀喂进去，让模型预测下一个 token。

也就是说训练样本会被拆成很多个条件预测：

|位置|给模型看的上下文|要学习的下一个位置|
|---|---|---|
|1|翻译：我喜欢机器学习。|I|
|2|翻译：我喜欢机器学习。 I|like|
|3|翻译：我喜欢机器学习。 I like|machine|
|4|翻译：我喜欢机器学习。 I like machine|learning|
|5|翻译：我喜欢机器学习。 I like machine learning|.|

这里的：

[  
y_{<i}  
]

就是标准答案中第 (i) 个 token 之前的前缀。

所以监督式 KD 中的：

[  
p_T(\cdot \mid x, y_{<i})  
]

意思是：

> 在输入 (x) 和标准答案前缀 (y_{<i}) 已知的情况下，教师认为下一个 token 应该是什么分布。

---

# 2. 监督式 KD 的完整流程例子

还是这个例子：

> 翻译：我喜欢机器学习。  
> 标准答案：I like machine learning.

## Step 1：准备标准答案前缀

训练时我们已经知道标准答案，所以可以构造这些上下文：

[  
x  
]

[  
x + \text{I}  
]

[  
x + \text{I like}  
]

[  
x + \text{I like machine}  
]

这些上下文不是学生生成的，而是数据集里标准答案给的。

---

## Step 2：教师在每个标准前缀上给概率分布

例如在第 4 个位置：

上下文是：

> 翻译：我喜欢机器学习。 I like machine

教师模型输出下一个 token 的概率分布，可能是：

|token|教师概率|
|---|--:|
|learning|0.82|
|translation|0.04|
|intelligence|0.03|
|learn|0.02|
|其他|0.09|

这就是：

[  
p_T(\cdot \mid x, \text{I like machine})  
]

注意，教师给的不是一个硬标签 `learning`，而是整个词表上的 soft distribution。

---

## Step 3：学生在同一个标准前缀上也输出概率分布

学生模型看到完全相同的上下文：

> 翻译：我喜欢机器学习。 I like machine

它可能输出：

|token|学生概率|
|---|--:|
|learning|0.35|
|translation|0.20|
|learn|0.15|
|model|0.10|
|其他|0.20|

---

## Step 4：让学生分布靠近教师分布

训练目标不是简单地让学生预测 `learning`，而是让学生的整个分布接近教师：

[  
D_{KL}(p_T(\cdot \mid x,y_{<i}) | p_S(\cdot \mid x,y_{<i}))  
]

通俗地说：

> 教师认为 learning 很重要，学生也应该提高 learning 的概率；  
> 教师认为 translation 不太可能，学生就应该降低 translation 的概率。

---

## Step 5：所有位置一起训练

所以一条答案会产生很多个蒸馏位置：

|位置|标准前缀|教师教学生什么|
|---|---|---|
|1|空前缀|第一个词大概率是 I|
|2|I|后面大概率是 like|
|3|I like|后面大概率是 machine|
|4|I like machine|后面大概率是 learning|
|5|I like machine learning|后面大概率是句号|

这就是“用答案路径作为上下文”。

---

# 3. 实际实现上是怎么做到的？

在 decoder-only LLM 里，训练时通常会把 prompt 和答案拼起来：

```text
输入序列：
[翻译：我喜欢机器学习。] [I] [like] [machine] [learning] [.]
```

模型用 causal mask，只能看当前位置之前的 token。

所以当模型在 `machine` 这个位置预测下一个 token 时，它能看到：

```text
翻译：我喜欢机器学习。 I like machine
```

但不能看到后面的：

```text
learning .
```

因此它是在标准答案前缀上预测下一个 token。

这就是为什么说：

> 监督式 KD 的上下文来自标准答案路径。

它不是让学生自由生成；它是把正确答案的前缀喂给学生和教师，然后比较两者的下一个 token 分布。

---

# 4. 那监督式 KD 的问题在哪里？

问题在于：训练时学生永远站在“正确前缀”上。

比如训练时学生看到的是：

```text
I like machine
```

然后学习下一个 token 应该是：

```text
learning
```

但推理时，学生可能自己生成成：

```text
I like machinery
```

这时候它下一步面对的上下文变成了：

```text
I like machinery
```

这个上下文不是标准答案路径，监督式 KD 训练时很少让它在这种状态下学习。

所以问题不是“它没有学每个 token 的概率”。

它确实学了每个位置的概率，但它学的是：

[  
p(\cdot \mid \text{标准答案前缀})  
]

而推理时需要的是：

[  
p(\cdot \mid \text{学生自己生成的前缀})  
]

两者的条件不一样。

---

# 5. On-policy KD 的流程

On-policy KD 反过来。

它先让学生自己生成答案。

比如输入还是：

> 翻译：我喜欢机器学习。

学生当前比较弱，生成了：

```text
I like machine learn .
```

这个答案不是标准答案，但它是学生真实推理时可能产生的轨迹。

然后 on-policy KD 用这条学生生成路径作为上下文。

于是训练位置变成：

|位置|给模型看的上下文|教师给反馈|
|---|---|---|
|1|翻译：我喜欢机器学习。|教师告诉第一个词应该怎么分布|
|2|翻译：我喜欢机器学习。 I|教师告诉 I 后面应该怎么分布|
|3|翻译：我喜欢机器学习。 I like|教师告诉 I like 后面应该怎么分布|
|4|翻译：我喜欢机器学习。 I like machine|教师告诉 machine 后面应该怎么分布|
|5|翻译：我喜欢机器学习。 I like machine learn|教师告诉这个错误前缀后面应该怎么继续|

这里的上下文是：

[  
\hat{y}_{<i}  
]

也就是学生自己生成的前缀。

所以 on-policy KD 中的：

[  
p_T(\cdot \mid x,\hat{y}_{<i})  
]

意思是：

> 在输入 (x) 和学生已经生成出来的前缀 (\hat{y}_{<i}) 下，教师认为下一步 token 应该是什么分布。

---

# 6. “根据已经生成的回答，为什么还能学到修正？”

这里要分两层理解。

## 第一层：它不能改掉已经生成的过去 token

普通自回归模型不能回头修改已经生成的 token。

如果学生已经生成了：

```text
I like machine learn
```

那么在这个序列内部，模型不能把过去的 `learn` 改成 `learning`。

所以 on-policy KD 里的“修正”不是指：

> 直接编辑已经生成的旧 token。

而是指：

> 在训练时，让学生知道：当自己走到某种前缀时，下一步应该怎样更合理；并且在犯错之前的那个位置降低错误 token 的概率。

---

## 第二层：它能在两个位置上学到东西

还是看学生生成的错误序列：

```text
I like machine learn .
```

### 位置 A：在错误发生之前

错误发生在第 4 个 token，学生把 `learning` 生成成了 `learn`。

在第 4 个位置，前缀是：

```text
I like machine
```

教师分布可能是：

|token|教师概率|
|---|--:|
|learning|0.82|
|learn|0.02|
|translation|0.04|
|其他|0.12|

学生当时却给了 `learn` 较高概率。

on-policy KD 会在这个位置训练学生：

[  
p_S(\cdot \mid x,\text{I like machine})  
]

靠近：

[  
p_T(\cdot \mid x,\text{I like machine})  
]

所以学生会降低 `learn` 的概率，提高 `learning` 的概率。

这就是最重要的“修正”：**以后别在这个前缀下犯同样的错。**

---

### 位置 B：错误已经发生之后

现在前缀已经变成：

```text
I like machine learn
```

教师会基于这个不完美前缀给出下一步分布。

它可能认为下一步比较合理的是：

|token|教师概率|
|---|--:|
|ing|0.45|
|.|0.20|
|about|0.08|
|其他|0.27|

如果 tokenizer 允许，教师可能会倾向于补出 `ing`，把 `learn` 接成 `learning`。

或者在另一种情况下，教师可能认为最好的办法是结束句子或接一个能让句子尽量合理的词。

这时候学生学到的是：

> 如果我已经生成了不太理想的前缀，接下来应该怎样把输出拉回到较合理的方向。

这就是“在错误状态下学习恢复”。

# 7. 一个更直观的例子

假设任务是回答：

```text
Q: The capital of France is?
```

理想答案：

```text
Paris.
```

学生 on-policy 生成了：

```text
London is
```

On-policy KD 会在学生路径上训练。

## 位置 1

前缀：

```text
Q: The capital of France is?
```

教师分布：

|token|教师概率|
|---|--:|
|Paris|0.95|
|London|0.01|
|France|0.01|

学生之前生成了 `London`，说明学生在这个位置错了。

训练后，学生会被拉向教师分布：提高 `Paris`，降低 `London`。

这会减少以后第一步犯错。

---

## 位置 2

前缀已经是：

```text
Q: The capital of France is? London
```

教师分布可能变成：

|token|教师概率|
|---|--:|
|is|0.30|
|,|0.25|
|.|0.20|
|but|0.10|

这里教师没法穿越回去把 `London` 改成 `Paris`。

但它可以告诉学生：

> 如果你已经写了 London，那么下一步怎么接比较不像乱码。

例如可能继续：

```text
London is not the capital of France; Paris is.
```

当然，并不是每个错误都能被完美修复。

这就是 on-policy KD 的优点和局限：

- 优点：学生学会在自己真实会遇到的状态下行动；
    
- 局限：如果前缀已经太差，教师反馈也可能不稳定或无法真正挽救。
    

---

# 8. 所以 on-policy KD 中的“修正”到底修正什么？

不是修正当前这条已经生成完的答案。

而是修正学生模型的参数，使它以后：

1. 在错误发生前的同一前缀下，更可能选教师认可的 token；
    
2. 在错误已经发生后的前缀下，更知道如何继续；
    
3. 对自己常见的错误状态更熟悉，而不是只会处理标准答案前缀。
    

所以更准确地说，on-policy KD 学到的是：

> 对学生自身生成分布下状态的改进策略。

---

# 9. 和监督式 KD 的关键差别再总结一下

假设标准答案是：

```text
I like machine learning.
```

学生自己生成的是：

```text
I like machine learn.
```

## 监督式 KD

训练上下文是标准答案路径：

```text
I
I like
I like machine
I like machine learning
```

学习目标是：

```text
在标准前缀上模仿教师
```

## On-policy KD

训练上下文是学生路径：

```text
I
I like
I like machine
I like machine learn
```

学习目标是：

```text
在学生自己会走到的前缀上模仿教师
```

---

# 10. 最核心的一句话

**监督式 KD 是“老师拿标准答案前缀考学生下一词”；on-policy KD 是“学生先自己写，老师再在学生写出的每个前缀上教它下一步该怎么写”。**
