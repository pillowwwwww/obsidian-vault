# 监督式 KD 与 On-policy KD 笔记

## 1. 核心区别

一句话：

- **监督式 KD**：在标准答案路径上，让学生模仿教师。
- **On-policy KD**：在学生自己生成的路径上，让学生模仿教师。

核心差别不是“谁给监督信号”，而是：

> 训练时的上下文来自哪里？

| 方法 | 上下文来源 | 监督信号来源 | 主要优点 | 主要问题 |
|---|---|---|---|---|
| 监督式 KD | 标准答案 | 教师模型 | 稳定，样本质量高 | 训练和推理分布不一致 |
| On-policy KD | 学生自己生成的答案 | 教师模型 | 更接近真实推理过程 | 学生生成差时，训练样本质量低 |

---

## 2. 监督式 KD 是什么？

监督式 KD 使用数据集中的标准答案作为训练路径。

假设任务是翻译：

```text
输入：翻译：我喜欢机器学习。
标准答案：I like machine learning.

把标准答案切成 token：
	I / like / machine / learning / .
```

训练时，模型不是自由生成整句话，而是使用标准答案前缀来预测下一个 token。

例如：

|训练位置|给模型看的上下文|要学习的下一个 token|
|---|---|---|
|1|翻译：我喜欢机器学习。|I|
|2|翻译：我喜欢机器学习。 I|like|
|3|翻译：我喜欢机器学习。 I like|machine|
|4|翻译：我喜欢机器学习。 I like machine|learning|
|5|翻译：我喜欢机器学习。 I like machine learning|.|

这里的上下文来自标准答案，所以叫：

```text
答案路径作为上下文
```

---

## 3. 监督式 KD 的训练流程

以第 4 个位置为例。

当前上下文是：

```text
翻译：我喜欢机器学习。 I like machine
```

### Step 1：教师输出概率分布

教师模型看到这个上下文后，给出下一个 token 的概率：

|token|教师概率|
|---|--:|
|learning|0.82|
|translation|0.04|
|intelligence|0.03|
|learn|0.02|
|其他|0.09|

### Step 2：学生输出概率分布

学生模型看到同样的上下文，也输出概率：

|token|学生概率|
|---|--:|
|learning|0.35|
|translation|0.20|
|learn|0.15|
|model|0.10|
|其他|0.20|

### Step 3：训练学生模仿教师

训练目标是让学生分布接近教师分布：

```text
让学生提高 learning 的概率
让学生降低 learn、translation 等不合适 token 的概率
```

所以监督式 KD 不是只学一个正确 token，而是学习教师对整个词表的概率判断。

---

## 4. 为什么监督式 KD 会有推理 mismatch？

因为训练时和推理时的上下文不同。

### 训练时

学生看到的是标准答案前缀：

```text
I like machine
```

它学习：

```text
在 I like machine 后面，应该生成 learning
```

### 推理时

学生需要自己一步一步生成。

如果它前面生成错了，例如：

```text
I like machinery
```

那么下一步的上下文变成：

```text
I like machinery
```

这个上下文不是标准答案路径，训练时可能很少见。

所以问题不是“学生没有学每个 token 的概率”。

问题是：

```text
监督式 KD 学的是：
p(下一个 token | 标准答案前缀)

推理时需要的是：
p(下一个 token | 学生自己生成的前缀)
```

上下文变了，模型的预测分布也会变。

---

## 5. On-policy KD 是什么？

On-policy KD 先让学生自己生成答案，然后让教师在学生生成的路径上给监督信号。

还是翻译任务：

```text
输入：翻译：我喜欢机器学习。
```

学生自己生成了：

```text
I like machine learn .
```

这条路径虽然有错误，但它是真实推理时学生可能走到的路径。

On-policy KD 会在这条学生路径上训练：

|训练位置|给模型看的上下文|教师给反馈|
|---|---|---|
|1|翻译：我喜欢机器学习。|教第一个 token 怎么生成|
|2|翻译：我喜欢机器学习。 I|教 I 后面怎么生成|
|3|翻译：我喜欢机器学习。 I like|教 I like 后面怎么生成|
|4|翻译：我喜欢机器学习。 I like machine|教 machine 后面怎么生成|
|5|翻译：我喜欢机器学习。 I like machine learn|教错误前缀后面怎么继续|

---

## 6. On-policy KD 为什么能学到“修正”？

这里的“修正”不是直接修改已经生成的旧 token。

它修正的是模型参数，让学生以后：

1. 更少犯同样的错误；
    
2. 已经进入错误状态时，也更知道如何继续。
    

---

## 7. On-policy KD 的两类学习信号

假设学生生成了错误句子：

```text
I like machine learn .
```

错误 token 是：

```text
learn
```

正确 token 更可能是：

```text
learning
```

### 7.1 错误发生前：学会以后少犯错

在生成 `learn` 之前，前缀是：

```text
I like machine
```

教师在这个前缀下可能给出：

|token|教师概率|
|---|--:|
|learning|0.82|
|learn|0.02|
|translation|0.04|
|其他|0.12|

学生会学习：

```text
下次看到 I like machine 时，
不要高概率生成 learn，
而要更倾向生成 learning。
```

这叫：

```text
在错误发生前纠偏
```

---

### 7.2 错误发生后：学会从错误状态继续

错误已经发生后，前缀变成：

```text
I like machine learn
```

教师会在这个错误前缀下继续给出下一步分布。

例如教师可能认为：

|token|教师概率|
|---|--:|
|ing|0.45|
|.|0.20|
|about|0.08|
|其他|0.27|

学生会学习：

```text
如果我已经生成到了 I like machine learn，
下一步应该怎样继续才相对合理。
```

这叫：

```text
在错误状态下学习恢复
```

## 8. 再举一个问答例子

任务：

```text
Q: The capital of France is?
A:
```

正确答案：

```text
Paris.
```

学生 on-policy 生成：

```text
London is
```

### 位置 1：错误发生前

上下文：

```text
Q: The capital of France is?
A:
```

教师分布可能是：

|token|教师概率|
|---|--:|
|Paris|0.95|
|London|0.01|
|Berlin|0.01|

学生之前生成了 `London`，说明它在这个位置错了。

训练后，学生会：

```text
提高 Paris 的概率
降低 London 的概率
```

### 位置 2：错误发生后

上下文已经变成：

```text
Q: The capital of France is?
A: London
```

教师不能回头改掉 `London`。

但它可以告诉学生下一步如何继续，例如：

```text
London is not correct; Paris is the capital of France.
```

所以学生可以学习：

```text
已经生成错误内容后，如何继续生成更合理的内容。
```

## 9. 二者流程对比

### 监督式 KD

```text
输入 prompt
    ↓
使用标准答案前缀作为上下文
    ↓
教师在标准前缀上输出 soft label
    ↓
学生在同样前缀上输出分布
    ↓
训练学生分布接近教师分布
```

特点：

```text
训练路径干净、稳定，但和学生真实推理路径不完全一致。
```

---

### On-policy KD

```text
输入 prompt
    ↓
学生先自己生成答案
    ↓
使用学生生成的前缀作为上下文
    ↓
教师在学生前缀上输出 soft label
    ↓
学生在同样前缀上输出分布
    ↓
训练学生分布接近教师分布
```

特点：

```text
训练路径更接近学生真实推理过程，但学生生成太差时，训练样本质量可能较低。
```

---

## 10. 最重要的理解

监督式 KD 的核心问题：

```text
训练时，学生总是在正确前缀上学习；
推理时，学生必须在自己生成的前缀上继续。
```

On-policy KD 的核心改进：

```text
训练时就让学生暴露在自己生成的前缀上，
因此更接近真实推理状态。
```

但 On-policy KD 的风险是：

```text
如果学生太弱，生成路径质量很差，
教师在这些奇怪上下文上的反馈也可能不稳定。
```

---

## 11. 一句话总结

```text
监督式 KD：老师拿标准答案前缀教学生。
On-policy KD：学生先自己写，老师再沿着学生写出的路径教它。
```
