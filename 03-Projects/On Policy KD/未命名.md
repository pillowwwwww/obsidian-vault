# OPD 近三年阶段性调研报告

时间范围为 2023–2026 年。当前最重要的结论是：

> OPD 已经形成清晰的方法谱系，但尚未形成统一 benchmark。现有论文共享“在学生自身状态上获得稠密监督”的思想，却在任务、初始化、teacher 形式、KL 方向、rollout 长度和评估指标上差异很大，不能直接横向比较数字。

FedOPD 位于其中一个尚未被系统研究的位置：现有 OPD 主要处理单个学生随时间产生的 train–inference mismatch，而 FedOPD 进一步处理多个客户端之间的 trajectory/correction mismatch。

## 一、OPD 的核心定义与研究主线

典型 OPD 流程是：

1. 学生根据当前策略生成轨迹；
2. teacher 在学生实际访问的 token history 上提供概率分布；
3. 学生最小化 teacher/student token distribution divergence；
4. 更新后重新生成新的 on-policy 轨迹。

它试图解决传统 SFT、SeqKD 和 supervised KD 的共同问题：训练时使用固定 teacher/gold 轨迹，推理时却访问学生自己的状态，错误会逐步累积。

## 二、核心论文之间的关系

### 1. 理论前驱：从固定 SeqKD 到分布级蒸馏

[FDISTILL，ACL 2023](https://aclanthology.org/2023.acl-long.605/) 将 sequence-level KD 统一为 f-divergence minimization，并说明 SeqKD、reverse-KL 类方法可以放在同一个分布框架下。它不是完整意义上的现代 OPD benchmark，但为后来比较 Forward KL、Reverse KL、JSD、skew KL 提供了理论语言。

它研究的主要是通用生成任务，不是专门的数学推理，也没有联邦场景。

### 2. 第一代标准 OPD：解决 exposure bias

[GKD，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/5be69a584901a26c521c2b51e40a4c20-Abstract-Conference.html) 是当前 OPD 最直接的源头：

- 在 student-generated sequences 上查询 teacher；
- 支持 Forward KL、Reverse KL、JSD；
- 可以混合 supervised 和 on-policy states；
- 覆盖摘要、翻译和算术推理。v

它建立的核心故事是：

> 学生应该在自己实际访问的状态上学习纠错，而不是只在 teacher/gold 状态上模仿。

[MiniLLM，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8ac015d409635f196f9e3e9dcfb9a94e-Abstract-Conference.html) 与 GKD 同代，但重点不同：

- 主要批评 Forward KL 的 mode-covering 特性；
- 使用 sequence-level Reverse KL；
- 通过 policy-gradient 风格估计优化；
- 主要研究 instruction following、长文本、校准和 exposure bias。

所以二者关系不是“新旧版本”，而是两条互补主线：

- GKD：强调 on-policy state distribution；
- MiniLLM：强调 divergence direction 与生成分布形态。

### 3. 第二代：承认纯 OPD 本身也有问题

[DistiLLM，ICML 2024](https://proceedings.mlr.press/v235/ko24c.html) 指出持续生成 fresh student trajectories 成本很高，并提出：

- skew KL；
- adaptive off-policy replay；
- 在保持部分 on-policy 相关性的同时复用历史样本；
- 相对已有方法最高报告约 4.3× 加速。

它与 FedOPD 很相关，因为它明确表明：

> student-generated states 并不天然都是高质量训练数据，OPD 必须同时处理样本效率和 noisy feedback。

[Speculative KD，ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/a2747a3844ca1e4667fbff3f558eb39b-Abstract-Conference.html) 从另一个方向解决同一问题。它指出：

- supervised KD 的状态过于 off-policy；
- 纯 OPD 的学生轨迹可能质量太低，teacher 对这些状态也不熟悉；
- 因此让学生先 propose token，teacher 替换排名差的 token。

SKD 实际上位于 teacher rollout 与 student rollout 之间，是一种混合 roll-in。它说明“越 on-policy 越好”并不成立；真正重要的是在状态相关性与轨迹质量之间取平衡。

### 4. 第三代：对不同来源的数据使用不同学习信号

[DistiLLM-2，ICML 2025](https://proceedings.mlr.press/v267/ko25a.html) 不再把 teacher-generated 和 student-generated 数据等价处理，而是：

- 提高 teacher responses 的概率；
- 降低低质量 student responses 的概率；
- 将二者组织为对比式目标。

其任务覆盖 instruction following、代码生成、偏好对齐和视觉语言扩展。它不是 FedOPD 的直接 baseline，但提供了一个重要观点：

> correction 的作用应取决于轨迹来自谁，而不是对所有轨迹使用相同 KL。

### 5. 对 OPD 风险与稳定性的研究

[On Teacher Hacking，ICML 2025](https://proceedings.mlr.press/v267/tiapkin25a.html) 研究 teacher 本身并非真实分布时，学生是否会过度优化 teacher 的缺陷。结果显示：

- 固定离线数据更容易出现 teacher hacking；
- 在线数据生成能够缓解；
- 关键因素之一是训练数据多样性。

这与 FedOPD 的关系很微妙：多客户端能够提高状态多样性，但错误地聚合不兼容 correction 又可能引入负迁移。因此“多样性”和“可聚合性”必须同时考虑。

2026 年的两项工作进一步聚焦 loss instability：

- [Entropy-Aware OPD，ICML 2026](https://research.ibm.com/publications/entropy-aware-on-policy-distillation-of-language-models--1) 指出 Reverse KL 在 teacher 高熵 token 上可能压缩多样性，因此在高熵位置加入 Forward KL。
- [Veto，ACL Findings 2026](https://aclanthology.org/2026.findings-acl.2094/) 同时讨论 Forward KL 在 unfamiliar tokens 上的异常梯度，以及 Reverse KL 的 diversity collapse，并通过 teacher/student 几何混合目标抑制有害梯度。

这两项工作说明目前没有证据支持“Forward KL 或 Reverse KL 永远最好”。loss、student capacity、teacher entropy、decoding metric 之间存在交互。

FedOPD 当前固定使用 Forward KL 是合理且明确的正式设计，但论文中应承认这是一个具体设计点，而不是 OPD 的公认唯一标准。

### 6. 长推理 OPD：成本成为主要问题

[Prefix OPD，ACL Findings 2026](https://aclanthology.org/2026.findings-acl.1276/) 发现 OPD 的主要有效信号集中在 reasoning prefix，只蒸馏学生轨迹前缀即可在数学与 OOD 推理任务上接近 full OPD，并报告 2×–40× FLOP 降低。

这和 FedOPD 当前 128-token training trajectory 很相关：当前截断不是完全没有文献依据，但本项目采用它是计算设置，而 Prefix OPD 会把“为什么只需要前缀”作为研究对象。两者不能直接等同。

## 三、这些论文的实验任务是否相同

并不相同，可以分成四组：

|任务群|代表工作|主要任务|常见指标|与 FedOPD 的可比性|
|---|---|---|---|---|
|传统序列生成|GKD、DistiLLM、SKD|摘要、翻译|ROUGE、BLEU|低到中|
|Instruction following|MiniLLM、DistiLLM、DistiLLM-2|通用指令、长文本、代码|perplexity、自动指标、judge score|中|
|数学与长推理|GKD、SKD、Prefix OPD、EOPD、Veto、OPSD|GSM8K、MATH/AIME 类及 OOD reasoning|EM、Pass@k、平均长度|最高|
|连续决策与长期学习|SDFT、SDPO、agent correction|continual learning、工具调用、代码代理|成功率、遗忘率、reward|研究动机相近，任务不同|

即使都使用 GSM8K，仍可能存在以下差异：

- base model 与 instruct model；
- 是否先做 CoT-SFT；
- teacher/student 是否同 tokenizer；
- 训练使用 Forward KL、Reverse KL、JSD 或混合目标；
- rollout 是 128、几百还是 16K tokens；
- greedy EM、sampling Pass@k 或 judge-based 指标；
- 最优 checkpoint 还是最后一轮；
- teacher logits 是完整词表还是稀疏近似。

因此不同论文报告的 GSM8K 数字不能直接组成排行榜。

## 四、是否已经形成标准 OPD benchmark

我的判断是：尚未形成。

目前只有相对稳定的“baseline 组合”，还没有统一 benchmark protocol。常见 baseline 是：

1. Base；
2. Gold SFT；
3. SeqKD；
4. 固定状态上的 token KD；
5. GKD/纯 OPD；
6. MiniLLM/Reverse-KL OPD；
7. 混合 teacher/student trajectories；
8. RLVR 或 GRPO。

缺少统一的是：

- 固定 teacher/student pair；
- 共享 SFT warm-start；
- 固定 rollout budget；
- 固定 full-vocabulary teacher access；
- 固定 KL 方向；
- 固定训练算力；
- 同时报告 task performance、EOS、长度、diversity 和训练成本；
- 多轮训练使用最后一轮还是挑选最优轮。

因此，FedOPD 当前的五方法、共享 SFT@10 初始化、固定 R9 主指标、完整 GSM8K/SVAMP 和 macro/worst/weighted 指标，实际上比很多单机 OPD 工作更接近“可复现实验协议”。

但它目前是一个 federated OPD controlled benchmark，而不是已经被社区采用的标准 benchmark。

## 五、OPD 向其他领域扩展的故事场景

OPD 正在从“模型压缩方法”扩展成一种更一般的 on-policy correction 原理。

### 1. 自蒸馏与特权信息

[Self-Distilled Reasoner，ICML 2026](https://aditya-grover.github.io/publications/) 让同一模型扮演两个角色：

- student 只看问题；
- teacher 额外看到 gold reasoning；
- 在学生轨迹上匹配两个 context-conditioned distributions。

它将“更大的 teacher”替换成“拥有特权上下文的同一模型”。

### 2. 持续学习

[Self-Distillation Enables Continual Learning，ICML 2026](https://openreview.net/forum?id=HlWA3V6iKF&noteId=DVexpZo7mv) 用 demonstration-conditioned model 作为 self-teacher，将示例中的新能力蒸馏回无示例模型，重点从模型压缩转向减少 catastrophic forgetting。

### 3. RL、代码和工具反馈

[Reinforcement Learning via Self-Distillation，ICML 2026](https://arxiv.org/abs/2601.20802) 将 runtime error、judge feedback 等文本反馈放入 context，让反馈条件下的模型充当 teacher，再把稠密 token 信号蒸馏回当前策略。任务包括科学推理、工具使用和竞争性编程。

这里 OPD 的故事变成了：

> 将环境提供的稀疏或文本反馈转换成 token-level credit assignment。

### 4. 音频—文本跨模态

[CORD，ACL Findings 2026](https://aclanthology.org/people/hai-tao-zheng/) 使用同一多模态模型的 text-conditioned distribution 作为内部 teacher，纠正 audio-conditioned rollout，并结合 token-level Reverse KL 与 sequence-level GRPO。

其故事不再是大小模型压缩，而是：

> 用强模态在弱模态实际访问的生成轨迹上进行 on-policy correction。

### 5. Diffusion language model

[COPSD，ACL Findings 2026](https://aclanthology.org/2026.findings-acl.1344/) 将 diffusion LM 后期解码阶段形成的更可靠分布蒸馏到早期阶段，用于修正 early-token prediction，提高推理效率。

这里 teacher/student 甚至不是两个模型，而是同一个 diffusion process 的不同时间阶段。

### 6. 跨 tokenizer 和异构模型

[TMLR 2025 的 ULD](https://openreview.net/forum?id=bwRxXiGO9A) 和 [NeurIPS 2025 的跨 tokenizer distillation](https://papers.neurips.cc/paper_files/paper/2025/hash/720f9f5dc751eb56952ae4fee2398f73-Abstract-Conference.html) 解决不同 vocabulary/tokenizer 下无法直接匹配 logits 的问题。

它们不都是严格 OPD，但对 FedOPD 最终的 heterogeneous-teacher 场景非常重要：如果不同客户端 teacher 不共享 tokenizer，“完整词表算术混合”就不能直接定义，必须先建立共同语义支持或 token alignment。

## 六、对 FedOPD 论文故事的直接启示

FedOPD 最自然的定位不是“提出另一个更好的 OPD loss”，而是：

> 单机 OPD 解决时间方向上的 state-distribution mismatch；联邦 OPD 还存在客户端方向上的 trajectory 与 correction mismatch。

可以将现有研究缺口表达为：

- GKD：学生是否在自己的状态上学习；
- SKD：这些学生状态是否足够高质量；
- DistiLLM：这些状态是否值得重复生成；
- EOPD/Veto：teacher correction 是否稳定；
- FedOPD：一个客户端上的 correction 是否仍适用于其他客户端。

目前检索到的工作里，还没有形成针对以下问题的标准答案：

- 多客户端的 OPD correction 如何聚合；
- correction 正迁移率如何测量；
- client-local teacher evidence 如何转化成公共信号；
- 如何同时报告平均性能、worst-client 和 OOD；
- 同一 correction 在不同客户端 trajectory 上是否仍然 on-policy。

因此，FedOPD 的独立贡献空间仍然清晰。

当前 Naive FedAvg-OPD 中出现的输出长度、EOS 和截断率波动，与 Veto、EOPD、SKD 所讨论的 OPD instability 在现象上相关，但目前只能作为诊断假设，不能直接宣称因果。后续应结合 R9 full 结果和 DA-FedOPD 对照，判断它究竟是普通 OPD 的暂态波动，还是联邦聚合造成的 correction mismatch。
